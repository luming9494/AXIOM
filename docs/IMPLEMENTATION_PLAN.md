## 1. 第一版交付边界

交付一次真实闭环：

```text
载入可信 TaskSpec → 校验环境/规则 → 建立基线
 → Pi 读取候选代码 → 修改允许的文件 → 保存 Diff
 → L0 检查 → L1 Smoke → 小规模真实训练与验证
 → Controller 根据结果和剩余预算保留/回退/停止
 → 独立评估 → 代码 + Checkpoint + 指标证据 + 报告
```

第一轮先限制为 **1 个候选、1 次训练尝试**，闭环通过后再开放最多 3 个候选。Baseline、Smoke、重试和最终评估分别记账；不得通过改名绕过规则中的总训练额度。

### 本轮不做

- 不扩展 Web、桌面端或远程 GPU。
- 不改 Pi 上游源码，不重写 Agent Loop、TUI 或 PyTorch Trainer。
- 不先引入 MLflow、向量数据库、多 Agent、复杂数据库服务。
- 不执行任意陌生仓库、自动下载数据、安装模型提出的依赖或使用付费 GPU。
- 不将“训练跑通”或“出现更高的 Proxy 分数”直接判为任务达标。

## 3. 首个 Tiny Task 的建议规格

以下为待实现的首个公开任务设计，不是已测成绩。

| 项目 | 建议 |
| --- | --- |
| 任务 | 二维非线性合成分类，小型 PyTorch 模型，CPU 执行 |
| 数据 | 固定生成器与种子；分别生成 train / validation / final-test，不依赖联网下载 |
| Baseline | 可运行但表达能力较弱的简单模型；实际分数与耗时先测量，不预填 |
| 允许改动 | 候选副本中的 `model.py` 与受白名单约束的训练配置 |
| 保护部分 | 任务规则、数据生成/切分、训练入口、评估程序、预算与判题程序不允许 Agent 修改 |
| 优化反馈 | 仅 validation 指标，用于候选筛选；不能读取最终测试反馈调参 |
| 最终交付 | 最佳合法候选、可加载 Checkpoint、Diff、真实训练记录与报告 |
| 目标阈值 | 在 Baseline 和人工可达参考实现实测后固定；Agent 启动后不得调整 |
| 达标口径 | 由 TaskSpec 明确完整 Tiny Task 的正式协议；短训练仅是 Proxy，不冒充正式达标 |

### 任务有效性先于 Agent 接入

不调用 LLM，先证明：

1. Baseline 能训练、保存、加载并完成评估。
2. 至少一个合法参考改动可以在预算内改善验证结果，避免设计成无解或纯猜谜任务。
3. 指标能通过独立程序重算，而非直接信任训练脚本输出的 JSON。
4. final-test 不反馈给优化循环；最终判定结束后不得依据测试结果追加候选。
5. 测量完整流程耗时，再固定任务预算与阈值；不保证跨硬件相同耗时。

### 初始预算建议

先测试“10 分钟墙钟、1 个候选、固定少量 epoch”的单轮配置是否足够；这是起始试验配置，不是性能承诺。Token 上限、单次输出上限与重试上限在首次付费模型验证前确定，记录 LLM 与训练的独立开销。

后续小任务可评估 10–30 分钟、最多 3 个候选的配置。计费不明确时输出未知或估算值，不填 0，不声称已实现严格费用保证。

## 4. 工作包与验收门槛

按顺序推进，每个工作包保持可单独检查的提交；以下编号仅为本地计划编号。

### WP-01：锁定任务和环境，不调用 LLM

**工作**：建立合成分类任务、独立 Python 环境说明、Baseline、参考改动、L0/L1 命令和独立评估程序；记录数据/协议版本与实际耗时。

**验收**：从干净输入手工运行到可加载模型；来源文件、种子与指标可重算；固定正式评估口径、阈值、可改文件和默认预算。

**产出**：`examples/tiny-ml-task/` 与无需密钥的测试。数据运行时生成；权重与运行日志写入被忽略的私有输出目录。

### WP-02：Pi 真实操作 ML 项目——已实测通过

**工作**：阅读锁定版本的 SDK/Extension/安全文档和示例，提供受限工具、候选副本、Diff、固定 Smoke 执行与事件记录。

**验收必须全部满足**：

1. 模型通过 Pi 工具读取模型代码，识别输入、输出和原始结构。
2. 模型自己生成 MLP 修改，在授权候选副本中执行，不修改原始项目。
3. 通过受限工具运行 L0 与真实 Smoke，不接受任意 Shell。
4. 模型读取独立评估结果，正确区分 Smoke 通过与正式性能达标。
5. 留下真实代码 Diff、Pi 工具开始/结束事件、命令日志和产物索引。
6. 模型实际发起的越界写入与非法命令都被阻止，保护文件未变化。

**集成决定**：先用 SDK + 显式 customTools 验证，便于自动验收与保存事件；不依赖环境中的 TUI/扩展发现，也没有重写 TUI 或 Pi Loop。后续可把同一工具契约接到 Pi 原生终端。

**当前边界**：只允许可信 Tiny Task 的简单 Sequential 网络；AST 白名单不是 OS 沙箱。安全上限为最多 12 次模型请求、每次 2048 输出 Token、32 次工具操作、一次 Smoke、180 秒会话 deadline 与每个子进程 60 秒；这些不是跨实验预算系统。

**产出**：[WP-02 验证记录](WP02_VALIDATION.md)、可重跑 CLI、候选与报告；不调用参考模型替 Agent 完成修改，不用模拟轨迹冒充真实调用。

### WP-03：第一次自主模型优化——下一步

**工作**：从“请改成 MLP”的明确指令升级为“在规则内改进验证结果”。接入可信 TaskSpec 和单轮 Controller，建立 Baseline，允许一个模型自主选择的合法候选，通过检查后训练与独立验证；按固定指标方向决定保留或回退。

扩展 `inspect_task / run_experiment / get_run_result` 契约，保留已验证的路径、代码与命令门禁，不先开放任意 Shell。单候选仍有超时与调用上限，不因尚未建设完整预算系统而无限执行。

**验收**：真实模型自主选择改法而非照指定结构改写；真实训练/验证，产生可加载模型、Diff、比较依据及正确的保留/回退决定。指标不提高也能交付 Baseline；最终测试不用于改进循环。必须通过此包，才开启多轮实验。

### WP-04：多轮实验与任务级预算

**工作**：把单轮扩展为有限候选循环；实现墙钟、Token、实验次数、重试、资源与成本记录；预算耗尽停止新增执行，并定义如何处理已运行的任务。加入取消、进程树清理与事件驱动等待，避免 LLM 轮询。

**验收**：零剩余额度不能启动任务；失败训练也计入消耗；超时后核验进程退出；同一任务能按真实反馈多轮保留/回退/停止。缺少 usage 时明确降级策略，不能无限追加请求。

**Token 边界**：区分请求前保守预留与请求后 actual usage。限制单次输出；供应商缺失 usage 或取消后计费未知时记录不确定性，保守停止，不声称绝对精确付费硬上限。

**资源边界**：计算时间不等于墙钟时间；未实现精确资源计量时使用进程 deadline/训练步数约束，并标记缺口。

### WP-05：完整 MVP 交付与失败评测

**工作**：完善任务摘要、候选历史、结果、Diff、Checkpoint、环境与复现命令；独立最终评估，补充规则违规、错误来源、模型报错、取消与预算耗尽反例。

**验收**：区分 `target_met / best_effort / budget_exhausted / blocked / failed / cancelled`，保留最佳有效结果与停止原因。模型自由文本不是判题依据，真实文件与确定性报告才是依据。

**MVP 门槛**：WP-01 至 WP-05 均完成，交付真实 Agent 的有限预算优化产物；WP-02 通过仅证明操作链路，不等于优化 MVP 已完成。

## 5. 最小实现结构（建议，不是现有目录）

不立即拆多包；先沿用现有 TypeScript 项目，按职责逐步新增：

```text
src/
  task/           TaskSpec、状态、预算与 Controller
  execution/      候选目录、白名单命令、子进程与超时
  agent/          Pi 集成和科研工具契约（避免与现有 agent.ts 混淆）
  reporting/      任务摘要与交付清单
examples/
  tiny-ml-task/   公共合成任务、Baseline 与允许修改的模型模板
  tiny-ml-eval/   受保护的训练/评估入口与任务判题器
tests/           TypeScript 单元/集成测试及 Python 测试入口
private/tasks/    运行时 Task/Candidate/Run、日志、模型与报告；不提交
```

具体拆分以首轮代码量为准，不为了目录完整而提前重构。保留 `src/research.ts`、`src/table.ts` 和已有命令，按需复用其证据/报告能力。

建议 Task 目录至少持久化：可信输入快照、候选 Diff、Run 元数据、事件轨迹、预算快照、最终结果与交付路径。初期允许 JSON/JSONL + 原子写入，不先建设数据库服务；不承诺初版能恢复任意中断的训练。

## 6. 代码执行的安全底线

**目录白名单、Git Worktree 和 subprocess 都不是安全沙箱。** Python 模型代码在运行时仍可能读取宿主文件、联网或派生进程；不能因编辑工具受限就宣称任意代码执行安全。

首轮只运行本仓库可审查的合成任务，在用户明确授权下执行候选代码，并要求：

- 执行环境不携带模型密钥等敏感环境变量；使用独立工作目录和最小环境。
- 评估器、数据切分和 TaskSpec 不可由 Agent 的编辑工具修改；记录其版本/哈希。
- 检查路径、文件类型、允许改动范围与运行配置；保护原始工作区。
- 子进程使用明确 argv，不拼接模型生成的 Shell；限制输出、执行时长和并发。
- 运行前展示隔离能力与残余风险；没有 OS 级隔离时，不支持不可信第三方代码。
- 后续依据本机能力选择容器或其他 OS 级隔离，才能承诺更强的网络、文件与进程权限限制。

只靠代码审查或哈希不等于可证明训练没有偷看测试集。初版的独立判题用于可信样例的客观验收，不宣传为防恶意候选的完整竞赛沙箱。遇到需执行不可信仓库或严格保护测试集的任务，先补隔离能力，否则 `blocked`。

## 7. 测试矩阵

| 层级 | 必测内容 | 是否需模型/训练 |
| --- | --- | --- |
| 现有回归 | import/export、来源和 Web 数据逻辑 | 无 LLM |
| Controller 单测 | 规则不可改、预算、状态、候选选择、重复请求 | 无 LLM；可用明确标记的假执行器 |
| Python 任务测试 | 数据切分、Shape、训练/保存/加载、重算指标 | CPU，少量训练 |
| 执行集成测试 | 越界、受保护文件、非零退出、输出超限、超时/取消、进程清理 | 无 LLM |
| 证据反例 | 缺失/篡改指标、错误 Run、Proxy 冒充正式结果 | 无 LLM |
| 真模型冒烟 | 请求成功、工具调用、脱敏与失败传播 | 显式开启，有 API 成本 |
| Tiny Optimize E2E | 读改代码、真实训练、有限反馈与交付 | 显式开启，有模型和计算成本 |

模拟执行器只验证控制逻辑；报告必须区分模拟测试和真实训练。日常不自动启动付费调用。正式引入隐藏测试后，其分数只用于最终判定，不进入候选反馈上下文。

## 8. 提交与推进规则

建议按以下主题拆提交，均采用英文前缀 + 中文说明；不提前建立空壳模块：

1. `test(ml): 新增可复验的 Tiny 分类任务与独立评估`
2. `feat(agent): 接入真实受限工具调用与执行事件`
3. `feat(task): 新增任务规则与候选执行控制`
4. `feat(optimize): 跑通单轮代码改动与训练评估`
5. `feat(budget): 实现有限迭代与超时取消`
6. `test(optimize): 补充预算合规与交付失败场景`

每个提交说明实测内容与未验证部分；需求/架构改变须另行记录。不重写 Pi 上游，不改已经完成的产品需求来迁就测试。

### 紧接着开始的任务

**接着做 WP-03**：在已验证的受限工具链上，让模型自主选择一次改动、完成真实训练并与 Baseline 比较。不要把 WP-02 的固定 Smoke 请求包装成自主优化。

付费模型验证仍须显式启动；日常回归不自动调用 API。涉及新依赖或执行环境时先说明用途，不改全局 Python。

## 9. MVP 之后再排期

- 在同一控制器上增加 Ablate 和 Reproduce 的最小任务。
- 建立 T1/T2 任务集，与同模型/同预算的 Pi 对比。
- 再做独立 Python Runner、远程 GPU、审批、幂等与恢复。
- 最后根据真实使用需求决定 Web/桌面入口，而不是默认恢复页面扩展。
